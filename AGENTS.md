# AGENTS.md

## Project

ESP-IDF v5.x firmware for the Waveshare ESP32-S3 Touch LCD 7 board, using LVGL 9 through `esp_lvgl_adapter`.

## Layout

- `main/` — hand-written application sources.
- `components/` — vendored board/LCD port.
- `managed_components/`, `build/` — generated by ESP-IDF; do not hand-edit.
- `sdkconfig*` — project configuration; change through `idf.py menuconfig` where possible.

## Build and verification

The ESP-IDF environment must be exported first (`IDF_PATH` set and the Xtensa toolchain on `PATH`). From an ESP-IDF shell:

- `idf.py build`
- `idf.py -p <PORT> flash monitor`

Plain `cmake --build build` fails unless that environment is active; the existing `build/` CMake cache contains machine-specific absolute paths. No lint or typecheck scripts are configured in this repository.

## Code conventions

- Application sources under `main/` are mixed C (`.c`) and C++ (`.cpp`); headers use a `.hpp` suffix regardless of the implementation language.
- C++ is supported by the ESP-IDF toolchain here, but functions shared with C sources need explicit C linkage. Wrap declarations in `my_sleep.hpp` / `salt_tab_main.hpp` with `#ifdef __cplusplus` / `extern "C"` guards; `extern` alone does not prevent name mangling. `app_main` must also be `extern "C"` if moved to a `.cpp` file.
- Headers should contain declarations only. Do not define variables with static storage in a header.
- Define a short log tag in each `.c` / `.cpp` file that logs: `static const char *TAG = "salt_tab";`. Do not use `__FILE__` for `ESP_LOGx` tags; it expands to a build-path-dependent full filename and clutters logs.
- Use `ESP_ERROR_CHECK` for ESP-IDF init calls, and keep LVGL API access under `esp_lv_adapter_lock()` / `esp_lv_adapter_unlock()`.
- Use LVGL 9 APIs (`lv_button_create`, `lv_obj_align`, `LV_ALIGN_BOTTOM_RIGHT`). `LV_ALIGN_OUT_*` values are only valid with `lv_obj_align_to()`, not `lv_obj_set_align()`.
- Do not commit changes unless explicitly asked.

## Review guidance

When reviewing changes, read the full modified files and check LVGL/adapter API usage against the headers in `managed_components/` before flagging an issue. Prefer concrete runtime scenarios over style preferences.
